# App 内完全卸载

入口：Aidente → 设置 → 关于 → 完全卸载 Aidente…。

点开按钮先显示清理范围，确认“卸载并退出”后才开始。系统组件由 macOS 自己的管理员授权弹窗确认，应用不接收密码。预览模式只展示确认说明，执行按钮禁用。

## 顺序与失败处理

1. 检查当前应用位于 `/Applications/Aidente.app`，没有另一个 Aidente 副本运行、更新或诊断导出进行中；拒绝重定向的清理路径。
2. 暂停策略、计划和写入任务，等待正在进行的电池历史保存结束。
3. 系统授权后，用已安装且签名有效的后台工具恢复默认电池 / 适配器控制。恢复失败会尝试重新启动原服务，停止后续清理。
4. 移除 Aidente 本地 LaunchDaemon、helper，以及已验证为本工具生成的 root 恢复备份；清理 helper 的专用 root 偏好。缺失恢复工具但仍有服务或固件快照时，停止并提示先修复服务。
5. 注销登录项，移除待发送和已显示的通知。
6. 清除当前账户的 Aidente 偏好域及有效的 ByHost 偏好，将历史、缓存、WebKit / HTTPStorage、保存状态、已识别的更新备份和临时诊断目录移入废纸篓。
7. 最后将 App 移入废纸篓并退出。前面任何一步失败，都不会继续移除主 App，界面会报告错误，保留重试入口。

普通“关闭管理充电”通过已经授权的服务恢复接管前的系统策略，服务保持安装但停止控制，不再为日常开关反复索要管理员密码。只有“完全卸载”才在系统授权后移除服务及清理恢复备份。

## 范围

- 只清理 Aidente 的确切路径 / 标识符，不扫描或清理其他账户。
- 不修改官方 AlDente 的应用、服务、设置或授权数据。
- 不删除下载的 DMG、源码目录和用户另存的诊断包。
- 系统自行管理的统一日志、崩溃报告、通知权限记录等不保证由 App 清除。
- App 和历史等用户文件移入废纸篓，可由用户自行恢复或清空；root 后台组件和恢复备份在成功恢复充电后移除。
- 旧式嵌入服务若仍在注册，需要先用“修复控制服务”迁移到当前方案；不会跳过充电状态恢复直接删除。

## 验证方式

`zsh BuildSupport/test_uninstall.sh`：共享路径 / 执行顺序检查及生产 shell 脚本的临时目录替身测试。

测试中只替换固定系统路径、期望 uid 和系统工具；运行在临时目录，模拟恢复成功 / 失败、孤立固件快照、符号链接和未知备份。不会执行真正的管理员授权、删除 `/Library` 文件、恢复硬件或将本机 App 移入废纸篓。

构建和上述检查通过不等于真实卸载已完成实机验收。本轮不自动安装或卸载真实系统组件。

## 本轮检查结果

- macOS 27.2 / arm64 构建及签名完整性检查通过。
- 26 项路径白名单 / 清理顺序检查、11 项 shell 临时目录场景、11 项管理员脚本文法与签名读取检查通过。
- 原有 186 项逻辑检查通过。
- UI 预览中验证了入口、清理范围、禁用的执行按钮和取消操作；未执行真实卸载。
